## Reporting a Vulnerability

**Please do not open public GitHub Issues or Pull Requests for security vulnerabilities.** 

We take the security of this project seriously. If you discover a security vulnerability, we appreciate your help in disclosing it to us responsibly.

### How to Report

Please report security vulnerabilities privately by:
* Opening a confidential **Private Vulnerability Report** directly under the "Security" tab of this repository (Recommended).
* Or by emailing us at: **security@yourdomain.com** (Replace with your actual security email).

To help us act quickly, please include the following details in your report:
* A description of the vulnerability and its potential impact.
* Clear, step-by-step instructions to reproduce the issue (including any proof-of-concept code or scripts).
* The specific version(s) of the project affected.

### What to Expect

Once a report is received, you can expect the following timeline and process:

1. **Acknowledgment:** We will acknowledge receipt of your report within **48 hours**.
2. **Evaluation:** Our team will investigate the issue and determine if it is a valid vulnerability. We may contact you for further clarification during this stage.
3. **Status Update:** Within **7 days** of acknowledgment, we will notify you whether the vulnerability has been accepted or declined. If declined, we will provide a clear explanation.
4. **Fix & Advisory:** If accepted, we will work on a patch. We aim to release a security fix and a public Security Advisory within **30 days**, depending on the complexity of the issue.

### Attribution

We believe in giving credit where it's due. If your report leads to a security patch, we will gladly credit your name or organization in the release notes and Security Advisory (unless you choose to remain anonymous).

Thank you for helping keep our community safe!
